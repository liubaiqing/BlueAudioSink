# 蓝音频双端界面规范

BAS2 连接行为与边界见 [连接层实现](07-bas2-connection-design.md)。双端正式应用入口均使用 BAS2。

本规范以当前 Windows 接收端和 Android 发送端为设计基准。新增或修改界面时，先在现有控件和布局中找到对应做法。需要引入新控件、改变交互层级或更换 UI 技术栈时，先更新本规范和对应端的实现规格，再修改代码。

## 双端共用原则

- 保持轻量工具的观感。浅色背景承载清晰的卡片和状态，留白用于分组。蓝色用于主操作、选中项和可调节值，次要操作降低视觉权重。避免渐变背景、装饰性动画和大面积厚重阴影。
- 首屏优先显示当前状态和下一步操作。用字号、字重和间距区分标题、关键数字与说明。能够用简短标签表达的内容无需长段解释。故障、断线和等待状态直接显示，不能只靠颜色或悬停辨认。
- 品牌使用同一蓝色音频图标。项目中文名“蓝音频”，英文全称“BlueAudioSink”，简称“BAS”。版本、作者、项目主页和 MIT 协议放在“关于”。平台各自使用适合鼠标或触屏的布局，不要求像素级跨端复制。
- 控件状态必须和真实能力同步。区分页面选中、连接建立、音频传输和实际播放；不可操作时呈现禁用，并在必要时说明原因。页面切换、查看设置和打开音量面板不负责启停音频链路。

## Windows 接收端

**技术栈**为 C#、.NET 8、Win32 窗口和 GDI 自绘。主窗口通过 GDI 双缓冲绘制；圆角、描边和圆点使用现有局部抗锯齿和 AlphaBlend。复用原生消息、托盘 Shell API 和现有输入路径。界面改动不得自行引入 WPF、Windows Forms、WinUI、WebView 或额外图形运行时。发布配置见 [SinkLite.csproj](../src/SinkLite/SinkLite.csproj)，边缘绘制与资源释放见 [电脑端实现规格](03-pc-implementation.md#控件边缘绘制)。

| 角色 | 当前基准 |
| --- | --- |
| 页面、卡片、边框 | `#F5F7FB`、`#FFFFFF`、`#DCE3ED` |
| 主强调色、浅蓝选中底 | `#0078D7`、`#E5F1FB` |
| 正文、次要说明 | `#17283F`、`#58667A` |
| 字体 | Microsoft YaHei UI，正文 14 DIP，说明 12 DIP，页面标题 20 DIP，核心指标 24 DIP |
| 窗口 | 默认 520 × 500 DIP，最小外框 480 × 500 DIP，设置侧栏约 88 DIP |

颜色、字体与缩放以 [MainWindow.cs](../src/SinkLite/Ui/MainWindow.cs) 的现有画刷、字体与布局为基准。绘制、点击命中和焦点框使用同一套 DPI 缩放及几何定义。

| 场景 | 控件用法 |
| --- | --- |
| 顶部导航 | 软件名只显示在系统标题栏。Windows 11 标题栏与页面共用底色。主页的蓝牙和 Wi-Fi 复用设备列表的文字标签样式，选中项用蓝字和短下划线。设置齿轮固定在主页右侧。进入设置后隐藏模式标签和齿轮，左上角的返回按钮回到原模式。 |
| 设置分类 | 左侧窄栏使用浅蓝选中底和细色条标示当前页。右侧从实际内容开始，不重复显示侧栏页名，也不为重复标题预留空间。设备类型使用紧凑文字标签。 |
| 主题 | 「常规」内并排提供跟随系统、浅色、深色。深色使用深蓝灰页面、略亮卡片和低对比度蓝灰边框。普通圆角描边和分隔线从当前主题取色，交互高亮使用蓝色。主页、设置、弹出列表、编辑框和标题栏使用同一套主题。 |
| 启用、连接、断开 | 用现有圆角按钮。当前可执行的主操作突出，次要操作用浅底或描边，禁用态与普通态可辨。 |
| 布尔偏好 | 使用行内开关，标签在左、开关在右。状态、焦点、禁用、悬停和点击反馈均沿用现有绘制。 |
| 音量、缓冲与设备 | Wi-Fi 音量使用可编辑百分比和减加按钮；有限档位用紧凑选项；设备用列表或下拉，单页隐藏分页。 |
| 状态、指标与帮助 | 状态卡显示短标题及状态文字；网络延迟、缓冲与丢包率用大数字和小标签。细节按需展开。说明复用问号、悬停和已接入的 F1 帮助，实际错误直接呈现。 |

新增控件优先复用 `DrawButton`、`RoundFill`、`RoundBorder`、`Dot`、现有开关、选中行及帮助提示路径。自绘新增交互应明确鼠标、键盘焦点、禁用和命中范围。卡片轮廓保持现有细描边，不通过放大窗口解决信息堆积。

悬停高亮在命中区域变化时立即绘制，不等待帮助提示的550ms计时或周期状态刷新；同一命中区域内移动不重复绘制。鼠标命中、强制重绘和绘制路径不得枚举网卡或播放设备。慢速设备枚举在后台执行，完成后以窗口消息更新缓存；后台网卡刷新不持有界面读取的控制器锁。保持既有双缓冲和抗锯齿，不通过持续刷新或新增过渡动画掩盖延迟。

连接启停、模式切换、日志维护和偏好落盘不得阻塞窗口输入。连接动作串行执行，立即呈现忙碌状态并禁用冲突操作；任务完成通过窗口消息更新。设置先应用内存状态，后台合并保存，成功后才称“已保存”；失败提示“本次已应用，未能保存”，保留重试入口。日志任务展示进行中状态，缓存目录用于绘制，清理不持有绘制读取的长期锁。

Android音量滑条在主界面和悬浮窗共用本地手势草稿：拖动立即显示指针与百分比，网络回包不能把正在拖动的滑块拉回；松手保留最终值等待确认，断线或电脑权威修订冲突取消旧意图。生命周期感知收集状态，隐藏Activity停止页面收集，服务和悬浮窗按自身生命周期维持。刷新保留当前设备条目，立即发出发现查询并提供短暂进行中反馈，不改变当前连接。

## Android 发送端

**技术栈**为 Kotlin、Jetpack Compose、Material 3。主题统一由 [BlueAudioSinkTheme](../android/app/src/main/java/com/blueaudiosink/sender/ui/Theme.kt) 提供，依赖和 SDK 版本以 [app/build.gradle.kts](../android/app/build.gradle.kts) 为准。页面和应用内面板复用 Compose 控件。系统授权、通知和悬浮窗口仍通过 Android 平台 API 接入。界面需求不得自行引入其他 UI 框架。

| 角色 | 浅色主题 | 深色主题 |
| --- | --- | --- |
| 主强调色 | `#1B6EF3` | `#8FB4FF` |
| 页面背景 | `#F7FAFF` | `#0F141C` |
| 卡片 | `#FFFFFF` | `#161D28` |
| 次要正文 | `#44506A` | `#B9C4D6` |

优先使用 `MaterialTheme.colorScheme`、`typography` 和 `shapes`。控件默认颜色沿用当前 Material 3 主题，避免页面私自硬编码近似色。尺寸用 dp，文字用 sp。主页面内容左右留白 20 dp，齿轮和刷新图标按钮保留至少 48 dp 的触控区域和辅助描述。字符串通过 Android 字符串资源维护。

| 场景 | 控件用法 |
| --- | --- |
| 页面与设置 | `Scaffold`、`TopAppBar` 和圆角卡片。主界面右上是齿轮。设置第一行是音量悬浮窗，第二行是主题，本机信息和关于固定在最后两行。后续功能设置放在信息项之前。 |
| 状态与设备 | 顶部状态卡含状态点、状态文字和电脑名称。手动添加与刷新置于列表上方；常规条目显示设备名，地址放在需要的详情与确认界面。 |
| 缓冲档位 | 复用 Material 3 单选分段控件。低延迟、平衡、稳定互斥，使用同一选中样式。 |
| 发送主操作 | 用全宽主按钮，最小高度 72 dp。开始用主题主色，停止用主题错误色，禁用态清晰。 |
| 接收音量 | 手机主界面和通知悬浮窗必须直接共用 [ReceiverVolumeControl.kt](../android/app/src/main/java/com/blueaudiosink/sender/ui/ReceiverVolumeControl.kt) 及同一主题。沿用 0–100 的 Material 3 Slider、右对齐百分比、轨道间隙、末端圆点及同步/禁用态。 |
| 底部统计 | 丢包率和发送时长并列，大值配短标签。版本与作者集中在关于页。 |

[通知音量悬浮窗](../android/app/src/main/java/com/blueaudiosink/sender/ui/NotificationVolumeOverlay.kt) 用 WindowManager 承载 ComposeView，保留 `TYPE_APPLICATION_OVERLAY` 和 `FLAG_NOT_FOCUSABLE`。面板可拖动滑条，但不打开新的 Activity 或抢前台焦点。圆角 Surface 使用轻阴影，当前 elevation 为 4 dp，外侧预留 14 dp 透明空间供阴影过渡。调整位置、卡片尺寸或阴影时同时检查窗口边界，四角不能被矩形边界裁断。

主题与相邻设置共用单行 Material 3 `ListItem` 和卡片底色。右侧紧凑排列跟随系统（默认）、浅色、深色，使用小号标签；仅选中项使用主题主色容器，触控高度至少 48 dp。点按直接切换，选择保存到 App 偏好并即时应用于页面、系统栏和通知音量悬浮窗。

## 修改与验收

提交前用现有同类页面作对照，核对字号层级、留白、控件状态和文字。Windows 检查默认与最小尺寸及不同 DPI，覆盖键盘焦点、悬停和圆角边缘。Android 检查浅色、深色、较大字体和触控命中。改动音量面板时，在实机从通知打开面板，核对与主界面相同数值下的滑条外观、音量同步、四角阴影及前台焦点。结果记录在本地产物或 CI，具体操作见 [测试与验收](05-testing-acceptance.md)。
