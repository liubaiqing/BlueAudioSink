# BAS2 连接层目标规格

状态：设计已定型，分阶段实现中。现有应用入口仍使用 BAS1，完成集成和验收后再切换。旧测试补丁保存在本地 codex/pre-bas2-hotspot 分支。

## 正式入口切换规格

双端入口统一使用 BAS2，不提供 BAS1 音频回退。发现保留原 OFFER/身份查询的有界元数据格式，在 flags bit7 标识 BAS2 能力；仅用于地址收集和旧版识别，设备身份最终必须经 TCP hello 核对。发现覆盖每个实际接口的广播、网关和 TTL1 组播。电脑独立发现服务与播放接收器组合，手机独立发现服务向会话管理器补充同身份地址，界面不新增选路选项。

音量使用控制通道的 epoch/revision 比较后写入，电脑为权威；重连清除未提交的手机调音意图，心跳同步电脑侧变化。诊断批次通过独立异步工作落盘后应答，重试保持事件ID。防火墙更新为当前 EXE、本地子网、Private/Public 的 TCP 与 UDP 两条规则，旧规则不自动提权迁移。BAS2 应用包标明双端需同时升级，保留现有布局和控件。

## 当前实现边界

`Core/Bas2` 和 Android `net/bas2` 为独立连接层，尚未接管正式应用入口。已实现双端帧编解码、电脑串行会话裁决、控制握手、真实音频端口的 UDP 挑战确认、独立 TCP 音频连接、流代际校验、来源占用和请求去重。Android 控制客户端与有界 TCP 写入器已通过编译；写入阻塞看门狗运行在独立线程，采集线程不等待写线程退出。

电脑端回归工具 `tools/ConnectionRegression` 使用真实回环 TCP/UDP socket 验证握手、探测、停止、旧流丢弃、重复请求、来源占用和 TCP 备用传输。`PlaybackReceiver` 已将验证后的 UDP/TCP 音频接入现有播放引擎，并通过隔离输出设备检查 PCM、流切换和有限排空。隔离实机探针支持同一真实音乐片段的逐字节输出比对；验证位置在 WASAPI 前，不等同于实际声卡输出、手机采集授权或完整应用验收。设备发现、正式应用入口、音量和诊断控制消息、UDP持续健康检测与完整恢复验收仍待完成。

Android 网络清单由 `NetworkEnvironment` 独立维护：NetworkCallback 合并200ms内重复事件，2秒一次物理接口枚举补充热点，枚举失败保留上次完整清单并报告错误。`RoutePlanner` 是纯策略层，按稳定路径键排序并限制每轮最多64个候选；`RouteRace` 最多同时验证3条，15秒总预算，胜出时转交连接所有权，取消和失败关闭其余 socket。稳定路径键不包含清单代际，因此无关变化不会强制重连；异步结果仍须由上层会话核对当前连接尝试。以上组件已实现和单测，应用入口接入待完成。

Android `SessionCoordinator` 已实现：一个串行执行器负责目标、阶段、采集意图、心跳和退避；一个独立调度线程等待路径竞争结果，避免阻塞取消和网络事件。竞争结果必须匹配当前 attemptId 和用户目标代际才可转交。PCM 线程只读取已开放的音频连接；断开或停止立即关闭此闸门，旧尝试不能重新打开。网络恢复保留发送意图，用户断开清除目标及发送意图。只读快照使用查找、控制连接、身份确认、传输验证、就绪、发送、恢复、失败和停止状态；应用音量、诊断与 UI 入口仍待接入。路径竞争取消最多100ms内停止等待，不依赖失败路径及时响应。探测中的 UDP/TCP socket 也纳入关闭所有权，避免取消时遗漏尚未就绪的连接。

## 模块和所有权

### 播放链接入约束

WifiReceiver 提供不绑定任何网络端口的播放入口，接收已经验证的固定格式 PCM，而不重新封装 BAS1 报文。BAS2 的 PlaybackReceiver 独立拥有 ControlServer，按已验证会话及流代际驱动播放开始、收包、有限排空和断开。新流先分离旧消费者再预缓冲；停止后立即拒绝该流的迟到音频，但已经验证并进入接入队列的 PCM 必须先送入有限排空。断开或替换流则立即丢弃旧队列。UDP/TCP 使用同一重排、抖动缓冲、软件音量和 WASAPI 输出，不引入第二套音频处理逻辑。

接收回调仅投递到40帧（200ms）的有界队列，播放接入线程处理流状态及 PCM；诊断不在逐包 socket 回调内落盘。每5秒汇总传输接入数量和接入队列丢弃数量，区分 socket 前的传输问题和应用内排队问题。适配层停止先关闭音频入口，再释放控制服务、队列、接入线程与播放引擎。播放连接控制阶段仍与实际输出状态分开，健康控制连接不能掩盖输出失败。应用入口切换前用隔离回归和真实音乐片段核对，不提前覆盖正式包。

双端分为网络环境、设备发现、路径管理、连接会话、音频传输和诊断六层。LinkController/WifiController 是上层入口。会话状态只由单一串行执行器修改；界面、网络回调和读包线程投递事件。实时线程只处理有界音频队列，不做磁盘写入、网卡枚举或界面操作。关闭取消任务并等待资源释放，所有回调校验连接尝试及网络代际。

设备身份长期保存；RouteCandidate 记录本地接口/Network、地址与掩码、远端端点、网络代际、最近成功及探测结果。ConnectionSession 持有当前控制连接、会话ID、流代际和选中路径。ConnectionSnapshot 只读发布连接与播放两个独立状态。

网络候选按最近成功、同子网、明确指定顺序，最多三个并发。Android 分别维护 Network 和热点接口；热点连接以实际 TCP 本地地址约束后续通道。Windows 从控制连接实际本地地址建立对应 UDP 路径。健康路径不因无关接口变化重建；当前接口丢失立即恢复。网卡名称只辅助过滤，不作为可达性证据。

## 发现与会话

逐接口 UDP45678 子网广播、网关单播和 IPv4 组播224.0.0.167（TTL1），按设备ID归并地址。已知/手动地址可直接探测，禁止无界扫描。TCP45678 控制由手机发起，单连接超时2秒，一轮15秒。控制帧为小端u32长度+UTF8 JSON（1..16384字节），字段 type、requestId、sessionId、body，protocol=2。JSON必须是对象；长度和结构异常关闭该连接。

消息包括 hello/welcome、probeReady、pathConfirmed、heartbeat/heartbeatAck、start/startAck、stop/stopAck、volumeGet/volumeSet/volumeState、diagnostics/diagnosticsAck、error。有副作用的请求使用递增非零u32 requestId，重复请求返回缓存结果，乱序/过期请求不执行。身份核对后电脑分配随机128位sessionId；手机进程有随机instanceId。会话令牌是来源隔离，不是密码学认证。默认仅可信局域网，不宣称加密。

身份确认后验证 UDP 音频端口（默认45679）：手机发送16字节随机挑战，电脑从相同音频端口原样回复，手机通过TCP确认；匹配会话、挑战和路径后才就绪。1.5秒未确认则尝试TCP45679，先提交当前会话令牌；仅选中控制会话可发送。TCP音频独立于控制。

BAS2 UDP固定40字节头（小端）：magic BAS2[0..3]、type u8[4]、flags u8[5]、headerSize u16=40[6]、sessionId原始16字节[8..23]、streamEpoch u64[24]、seq u32[32]、timestampUs u32[36]。sessionId以16字节十六进制编码用于JSON，不使用Guid混合端序编码。type1音频严格960字节PCM；type2探测和type3探测回复严格16字节挑战。音频epoch必须非零；探测epoch为0。flags仅音频bit0不连续。未知类型、长度、标志拒绝。TCP音频逐帧小端u32长度+同一BAS2音频包，逐帧严格校验。音频固定48kHz/16bit/双声道/5ms，单UDP报文1000字节。

start由电脑分配非零随机u64流代际，startAck后允许发包。路径/传输改变先废弃旧流，旧包不进播放队列。沿用现有重排、PlayoutBuffer和WASAPI消费。停止发送不释放有效控制连接。

## 恢复与状态

连接状态为查找、控制连接、身份确认、传输验证、就绪、恢复、停止和失败。播放另分无音频、静音、缓冲、输出及故障。心跳2秒，6秒无响应恢复。UDP发送中1秒无接收确认且控制健康时探测，2秒不能恢复转TCP。TCP发送队列最多40帧（200ms）；持续阻塞300ms重建数据连接和流代际，记录丢弃。健康TCP保持至本次发送结束，下次重新优先UDP。自动重连按1/2/4/8/15秒退避并加抖动，明确断开取消恢复。

只允许一手机传音，其他手机收到busy；用户明确选择才替换。采集授权仍有效则恢复发送。每次新连接就绪将手机媒体音量归零；电脑音量权威，重连清旧调音意图。保持现有UI，兼容模式用短标签，详细信息放提示和日志。禁止因超时直接归因为防火墙；VPN拒绝绑定等直接证据使用独立错误码。

## 诊断与防火墙

记录appRunId/attemptId/pathId/sessionId/streamEpoch、实际端点、阶段耗时、系统错误码及状态变更。音频统计5秒汇总。手机异步持久化最多7天/2MiB/4096条，任一先到即轮转；通过TCP控制限速补传，电脑落盘后确认，eventId识别至少一次交付。首次连接失败可手机导出。不保存音频、密码、MAC、VPN节点配置；分享网络地址需提醒。

用户主动授权后仅为当前EXE开放Private/Public的本地子网TCP/UDP必要端口，不含Domain。升级旧规则需明确更新操作。规则正确性、当前接口适用性、探测结果分别展示。

## 验收与交付

测试取消/迟到/重复/竞争/旧流、发现及各端口分别受阻、TCP背压、多手机隔离、旧调音不重放。实机覆盖路由器、热点、WiFi+热点并存、电脑热点、网线、虚拟网卡、VPN允许/禁止绕过。路由器和热点往返5轮无需重启，不重复电脑记录，无关接口变化不掉音。UDP/TCP各1小时检查内存/句柄/线程/队列/声音与日志。已知设备正常5秒内就绪，失败15秒内解释。每阶段本地提交，完成后交付测试包与验收结果，发布另行执行。

连接层独立实机探针采用隔离 Android applicationId 和测试端口，不替换用户正在使用的双端应用。手机使用真实 `NetworkEnvironment`、`SessionCoordinator` 和 `ControlConnection`，发送固定规则的960字节测试PCM，电脑逐包核对内容。电脑探针不打开声卡；此项验证实际网路和帧完整性，不作为采集授权、播放音质或应用入口验收。UDP故障注入只在测试服务器上禁止挑战回复，验证客户端自动选择TCP，不修改系统防火墙。测试产物、网络地址和执行结果仅放入本地忽略的 artifacts。
